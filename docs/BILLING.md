# 請求書システムの仕様メモ（作業前に必ず読む）

勤怠・請求管理システム（kintaikanri）の請求まわりの仕様と、取引先ごとの運用ルール。
AIが作業するときの前提。変わったら必ずこのファイルも直す。

## 基本ルール
- 本番反映（main へ push → Vercel 自動デプロイ）は、ユーザーが「反映して」と言ったときだけ。
- DBの直接変更（Supabase `bifnfgcqiyztpwvxxrcn`）は本番に即反映される。金額・送付済みの請求に関わる変更は、先に内容を見せて確認を取る。
- お金の数字は、計算し直して一致を確認してから出す。
- 承認・送信は原則ユーザーが管理画面で行う。AIは下書きまで。
- 返信・説明は日本語。
- 見た目の変更は、確認を求める前に画像でプレビューを見せる。
- Vercel の自動デプロイが始まらないことがある。空コミットを push すると動くことが多い。MCP からの手動デプロイは権限がなく不可。

## データ構造
- 時刻はUTCで保存。JST = +9時間。月の範囲は `YYYY-MM-01T00:00+09:00` 〜 翌月1日。
- `Invoice`：`kind` = `WORK`（稼働分。請求書＋請求内訳書、訂正版あり）/ `EXTRA`（別途請求。請求書のみ）。
  `status` = DRAFT → APPROVED → FINALIZED（送付済み）/ REISSUED（訂正版で置き換え済み）。`sentAt` が送付日時。
- 訂正版は `請求番号-R2` のように revision を上げて新規作成（送付済みは直接書き換えない）。
- `Invoice.statement`（JSON）が内訳書の中身。`staff[]`（稼働日・dayPlaces・serviceExTax・serviceCalc・travel）、`clientExtras[]`（広告費など。store＋period がある行が広告費）、`manualLines`（品目の手入力）、`baseline`（作成時の値）。
- `Client.billingTerms`（JSON）が取引先ごとの請求設定：
  - `shiftBilling[]`：シフトから請求する条件（`contract` MONTHLY/DAILY、`rateExTax`、`staffName`、`fromMonth`/`toMonth`、`absenceDeduction: "YES"` で欠勤日割り控除、`flatTravelExTax`、`travelByStore`）
  - `shiftBilling[]` の `storeName`（店舗名）と `storeKind`（SHOP=ショップ / RETAIL=家電量販店）：スタッフがシフトを登録・編集するとき、その月に有効な契約（特定日だけの契約を除く）が1件だけで `storeName` があれば、店舗名の入力は出さず自動で入る（`src/lib/contract-store.ts`）。ショップは先頭に「キャリア名＋ショップ」が付く（au→auショップ / docomo→ドコモショップ / SoftBank→ソフトバンクショップ / 楽天モバイル→楽天モバイル）、家電量販店はそのまま。契約が複数ある人は従来どおり本人が入力（シフト登録の「店舗」画面：キャリアをボタンで選び、店の種類=ショップ/家電量販店をボタンで選び、店名だけ手入力。語尾の「店」は自動で付く。例: au＋ショップ＋築館 → auショップ築館店）。管理画面のシフト編集は手で直せる。`storeName` は `storeMatch` のどれかを含む名前にする。藤田＝「コジマ×ビックカメライオンモール名取店」（家電量販店）
  - `statementByStore`：内訳書を店舗別に分ける（表記揺れを照合）
  - `statementServiceLabel`：内訳書での「業務委託費」の呼び方
  - `statementMonthSuffix`：「〇月請求分」の表記（未設定＝請求分）
  - `amountEntry`：スタッフが金額を入力して送る専用リンク（token・staffId・approverName・carrier）
  - `recipientPresets`：店舗ごとの宛先（`label`＝店舗名、`emails`＝その店舗だけの宛先、`area`＝エリアの識別子）。`recipientAreas`：エリアごとの担当者（`key`・`label`・`people[]`＝`name`・`email`・`greet`）。`area` を選んだ店舗は、そのエリアの担当者のアドレスが先に宛先へ入り、その店舗だけの宛先が続く（`recipientPresetsOf`）。担当者を変えると、そのエリアの全店舗に反映される。`greet: true` の人（TSL/TL）は、メール本文の宛名の下に「〇〇 様」と書かれる。名前は送信前の確認画面の宛先に出る。担当者の登録・変更は今のところDB（`Client.billingTerms`）を直接直す。店舗ごとのエリアは、取引先の「請求先（店舗ごとの宛先）」画面で選ぶ。
  - `confirmBcc` など
- 消費税：請求合計に10%を切り捨て。個別に `statement.taxRounding = "HALF_UP"` で四捨五入にできる。
- 欠勤：シフトを取り消さず「打刻なし」で残す（取り消すと予定日から外れて満額扱いになる）。休み申請は `ShiftChangeRequest`（TO_OFF）で記録。

## 画面
- 送付済みの請求の詳細（`/admin/invoices/[id]`）：「メールを再送する」欄（登録済みの宛先をチェックで選び、新しい宛先を追加できる。追加した宛先は取引先の `invoiceEmails` に保存。請求ごとに宛先(`recipientEmails`)を決めている請求は、その請求だけに保存）と、送付履歴（`InvoiceSendLog`：初回送信・再送の日時・宛先）。再送は金額・請求番号・状態・`sentAt` を変えず、件名は「【請求書（再送）】」。「送信」「再送する」を押すと、先に確認画面（初回送信=青・再送=オレンジのラベル＋実際に送る件名・宛先・添付・本文。`previewInvoiceMail` で送信と同じ中身を作る）が出て、「送信する/再送する」で初めて送られる。
- 請求管理（`/admin/invoices`）：送付済みの月を選ぶと、合計売上（税抜・税込）・支払い予定（スタッフ報酬＋経費＋別途報酬＋広告費＋外注費）・粗利、スタッフ別の内訳を表示。粗利に固定費・税金は含まない。
- スタッフ詳細（`/admin/staff/[id]`）：月別の売上・報酬＋経費・別途報酬・粗利・振込済みと累計。
- 会社経費（`/admin/company-expenses`）：区分「外注費」（他社からの請求・税抜）だけが支払い予定・粗利に入る。自動繰り返しはない（毎月手で登録）。

- 振込関係（`/admin/payments`）の月別表：列は「受取・経費(明細つき)・別途報酬・支払い予定金額」。固定支払の支払い予定金額 = 受取＋経費＋承認済み未振込の別途報酬。振込完了の記録金額は押した時点の金額で、後から打刻を直しても変わらない（直す時は記録の金額を手で揃える）。
- 振込関係の月別表の内訳：受取の下に「〇月分・月固定/1日あたり」と計算式（月額÷予定日数×出勤日数、または日当×稼働日数、交通費の自動加算）、経費の明細、別途報酬（リファラル等）の明細（申請時の内訳行つき。固定支払の「振込完了」に含めて払った分は「振込済に含む」と表示）、支払い予定金額の計算式を出す。振込済みは「振込日」と「振込金額」を分けて表示（振込日＝振込完了を押した日時）。内訳は表示用で、金額の計算（`computeMonthlyEarnings`）は変えていない。
- 振込関係の「申請支払の人の振込残高」（`transfer-balance.tsx`。月ごとの行に状態バッジ「全額支払い済み／一部支払い済み／申請中／これから振込」・進み具合の線・「残り¥」、振込済みの履歴は折りたたみ）：現在の振込可能額残高（確定受取累計−振込済み。申請中は引かない＝2026-11-26変更。残高の計算は `computeTransferBalance` と同じ）と、月別（稼働月ごと）の確定受取・振込済み・申請中・未払い残、振込済みの履歴（振込日・振込金額・希望振込日）。申請は月に紐づかないため、振込済み→申請中の順に、古い月の確定受取から順に充当して「何月稼働分か」を決めている（計算上の割り当て。`src/lib/transfer-allocation.ts`）。充当は申請額（amount）ベース。実際の振込金額が申請額と違う履歴は注記を出す。承認済みの経費は稼働分と同じ「確定した受取」に足す（2026-11-25 決定。別途報酬は含めない・未決定）。
- 「振込完了」ボタンの警告：押した日（JST）が、固定支払は支払い予定日（土日祝の前倒し後）、申請支払は希望振込日と違うときだけ、確認ダイアログ（OKで記録）を出す。同じ日なら警告なしで1回で記録。振込日は「押した日時」のまま（実際の振込日の入力欄はない）。
- 変更履歴（`PaymentAuditLog`。スタッフ詳細 `/admin/staff/[id]` の「変更履歴」で新しい順に見る・最大100件）：対象は、振込（振込完了・取り消し・申請の却下・スタッフの振込申請）、金額設定（月の満額・手入力の支払い金額・スタッフの報酬設定＝支払方法/締め日/日当/月額/交通費。変わった項目だけ「変更前→変更後」）、経費（申請・承認・却下）、別途報酬（申請・承認・却下・振込済みの記録と取り消し）。管理画面は共通パスワードで個人を区別できないため、管理者の操作者名は各フォームの「操作者名」欄に入れた名前（前回の名前をブラウザが覚える。空欄は「名前なし」と表示。経費・別途報酬の承認は「確認者名」を使う）。スタッフ本人の操作は本人名を自動で記録。履歴の記録に失敗しても本来の操作は止めない。テーブルは `prisma/migrations/20261124010000_payment_audit_log`（本番DBへは Supabase で手動適用。デプロイより先に適用する）。シフト・打刻の修正の履歴は従来どおり別（`ShiftHistory`・`ClockRecordHistory`）。
- 紹介リファラル(渡辺)の自動計算（`src/lib/referral-auto.ts`・`referral-calc.ts`。設定は `ReferralLink`＝紹介した人・された人・会社取り分%・何月払いから自動計算するか。テーブルは `prisma/migrations/20261124020000_referral_link`、本番DBへは Supabase で手動適用し、デプロイより先に適用する）：振込関係（`/admin/payments`）を開くたびに、その支払い月の「承認済み」の別途報酬(REFERRAL)を自動で作る・更新する（レビュー者名「自動計算(リファラル)」）。リファラル = 日割り後の単価（請求書と同じ `staffFromRule` の業務委託費。請求は当月のシフト日数で日割り）− 会社取り分（日割り後の単価の10%・端数切り上げ）− 日割り後の本人支払い（`computeMonthlyEarnings`）。稼働月 = 支払い月 − 紹介された人の `fixedPaymentMonthOffset`（柴田=翌月払い→前月分）。出勤日数が増えるたびに月末まで再計算される。振込済み・却下の行は触らない。手入力のリファラル申請がある月は自動では作らない。紹介された人のうち1人でも計算できない（契約の店舗名・期間と合わない等）と、一部だけの申請を作らないよう何も作らず、画面に黄色の警告を出す。0円未満は0円。履歴は変更履歴（別途報酬）に記録。
- 経費の自動作成（`src/lib/expense-auto.ts`。設定は `StaffExpenseRule`。テーブルは `prisma/migrations/20261124030000_staff_expense_rule`、本番DBへは Supabase で手動適用し、デプロイより先に適用する）：振込関係（`/admin/payments`）を開くたびに、今月と先月の稼働月について、承認済みの経費（レビュー者名「自動計算(経費)」）を自動で作る・更新する。`KM`＝出勤の打刻があるシフトの店名が `storeMatch` を含む稼働日ごとに、片道km×2を走ったものとして、月の合計km×10円をガソリン代にする（高速代・駐車場代は本人が申請）。`FIXED`＝毎月の固定の経費。振込完了を記録した月は触らない。店名がルールに合わない稼働日は除いて計算し、画面に黄色の警告を出す。村上：ガソリン代は2026年11月稼働分から（西多賀14.1・東仙台6.7・塩釜14.8・仙台上杉5.1・村山駅西62.6 の片道km）、AI利用料3,000円（立替金）は12月稼働分から。10月分までは本人申請（承認済み）。村上は月額30万円固定（2026年10月稼働分から。9月分は `MonthlyEarningTarget` で165,000円）。
- 経費の払い済み記録（`Expense.paidAt`・`paidByName`。※申請支払の人の経費は2026-11-25から、振込残高の計算に含めて一緒に払う方式に変更。振込残高カードの「払い済みにする／取り消す」は廃止し、`markExpensePaid`・`undoExpensePaid` は画面から使わない。固定支払の人は従来どおり。以下は変更前の記述。`prisma/migrations/20261124040000_expense_paid`、本番DBへは Supabase で手動適用し、デプロイより先に適用する）：申請支払の人の経費は月末に別で払うため、振込関係の「申請支払の人の振込残高」カードの「経費（月末に別で払う分）」で、承認済みの経費ごとに「払い済みにする／取り消す」を押す（履歴は変更履歴の経費に記録。「これから払う ¥」と「すべて払い済み」を表示）。2026年10月分までの加藤・坂本の承認済み経費は、月末払い済みとして一括記録済み（払った日は月末の日付で、実際の日付ではない）。固定支払の人の経費は、これまでどおり「振込完了」に含む。
- スタッフ側の経費申請画面（`/expenses`）：自動で経費が入る人（`StaffExpenseRule` がある人）には、上に緑の枠「次の経費は自動で入ります（入力しないでください）」を出す（距離型＝ガソリン代、固定型＝名目と毎月の金額）。二重申請を防ぐため。重複の警告（同じ項目を手で申請したとき）はまだ。
- スタッフ側の「振込履歴」（`/payment/history`。旧「振込申請履歴」。`src/app/payment/history/page.tsx`）：申請支払の人は、上に「これまで受け取った額」（実際の振込額 `paidAmount`、記録がなければ申請額）と「まだ受け取っていない額」、申請中の別枠、「月ごとの受け取り」（管理画面の振込残高と同じ充当＝申請額ベース・古い月から）、「振込の履歴」（新しい順。振込日・実際の振込額・ここまでの合計。月をまたぐ振込は「明細を見る」で月ごとの内訳＝`splitTransfersByMonth`、古い月から順に充てた目安）を出す。却下は出さない。固定支払の人は、月ごとの振込（`FixedPaymentCompletion`。振込日・振込金額）と、タップで明細（稼働分＝振込金額−承認済みの経費−「振込完了に含む」別途報酬、経費・別途報酬の行、合計）を出す。
- 見積書の送信前の確認画面（`previewEstimateMail`。請求書の確認画面と同じ見た目）：詳細画面の「送付」「再送」、フォームの「保存して送付」を押すと、先に宛先（名前とアドレス）・件名・添付・本文の確認画面が出て、「送信する」を押すまで送られない（フォームでは先に保存だけ行い、「戻る」で送らずに詳細へ移る）。見積書のフォームは、取引先を選ぶと登録済みの店舗のボタンが出て、押すと店舗名と送信先が入る。見積書に送信先を入れていないときは、店舗名が登録済みの店舗（「店」・SB/ソフトバンクの違いは無視）に合えば、その店舗の宛先（エリアの担当者を含む）に送る。合わなければ取引先の登録に送る。
- コスモネット（2026-11-24 登録）：エリアは 青森・秋田（日景TSL）／岩手（千坂TSL）／宮城（宮坂TSL）／福島（竹内TL）。浅野AM（福島以外）と石沢様（全店舗）は全員宛先（To）に入る。店舗は SB秋田山王店＝青森・秋田、SBフレスポ富沢店＝宮城、SB奥州水沢＝岩手（所在地はソフトバンクの店舗ページで確認。取引上「SB奥州」と呼ぶ店も同じSB奥州水沢で、別の店ではない＝本人確認済み）。

- 振込可能額から引くのは「振込完了（PAID）」だけ（2026-11-26 決定。変更前は申請中も引いていた）：振り込める額 ＝ 確定した受取 − 振込済み。申請中（REQUESTING）の金額は引かず、管理者が「振込完了」を押した時点で引く。申請中の合計は `pendingAmount` で別に出す。管理画面の振込残高カードは、申請中を別枠で表示し、月ごとの残りからも引かない。全額払い済みの月は出さない（未払いが残る月だけ）。月への当てはめは、従来どおり古い月から順に自動。申請中の合計が振り込める額を超えたときは赤い警告を出す。スタッフの新規申請の上限は「申請中を除いた残り」（`requestableAmount` ＝ 振り込める額 − 申請中の合計、0未満は0）。画面（振込申請）にも「新たに申請できる額」を出し、サーバー（`createTransferRequest`）でも、これを超える申請は受け付けない（例：可能額4万円・申請中3万円なら、新たに申請できるのは1万円まで）。スタッフのホーム・振込申請の画面は、振り込める額（申請中を引く前）の下に「うち 振込申請中」を出す。加藤で検算：確定729,060−振込済み685,000＝44,060（申請中30,000は引かない）→30,000の振込完了後は14,060。
