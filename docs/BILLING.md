# 請求書システムの仕様メモ（作業前に必ず読む）

勤怠・請求管理システム（kintaikanri）の請求まわりの仕様と、取引先ごとの運用ルール。
AIが作業するときの前提。変わったら必ずこのファイルも直す。

## 基本ルール
- 本番反映（main へ push → Vercel 自動デプロイ）は、ユーザーが「反映して」と言ったときだけ。
- DBの直接変更（Supabase `bifnfgcqiyztpwvxxrcn`）は本番に即反映される。金額・送付済みの請求に関わる変更は、先に内容を見せて確認を取る。
- お金の数字は、計算し直して一致を確認してから出す。
- 承認・送信は原則ユーザーが管理画面で行う。AIは下書きまで。
- 返信・説明は日本語。
- 見た目の変更は、確認を求める前に画像でプレビューを見せる。
- Vercel の自動デプロイが始まらないことがある。空コミットを push すると動くことが多い。MCP からの手動デプロイは権限がなく不可。

## データ構造
- 時刻はUTCで保存。JST = +9時間。月の範囲は `YYYY-MM-01T00:00+09:00` 〜 翌月1日。
- `Invoice`：`kind` = `WORK`（稼働分。請求書＋請求内訳書、訂正版あり）/ `EXTRA`（別途請求。請求書のみ）。
  `status` = DRAFT → APPROVED → FINALIZED（送付済み）/ REISSUED（訂正版で置き換え済み）。`sentAt` が送付日時。
- 訂正版は `請求番号-R2` のように revision を上げて新規作成（送付済みは直接書き換えない）。
- `Invoice.statement`（JSON）が内訳書の中身。`staff[]`（稼働日・dayPlaces・serviceExTax・serviceCalc・travel）、`clientExtras[]`（広告費など。store＋period がある行が広告費）、`manualLines`（品目の手入力）、`baseline`（作成時の値）。
- `Client.billingTerms`（JSON）が取引先ごとの請求設定：
  - `shiftBilling[]`：シフトから請求する条件（`contract` MONTHLY/DAILY、`rateExTax`、`staffName`、`fromMonth`/`toMonth`、`absenceDeduction: "YES"` で欠勤日割り控除、`flatTravelExTax`、`travelByStore`）
  - `statementByStore`：内訳書を店舗別に分ける（表記揺れを照合）
  - `statementServiceLabel`：内訳書での「業務委託費」の呼び方
  - `statementMonthSuffix`：「〇月請求分」の表記（未設定＝請求分）
  - `amountEntry`：スタッフが金額を入力して送る専用リンク（token・staffId・approverName・carrier）
  - `confirmBcc`、`recipientPresets` など
- 消費税：請求合計に10%を切り捨て。個別に `statement.taxRounding = "HALF_UP"` で四捨五入にできる。
- 欠勤：シフトを取り消さず「打刻なし」で残す（取り消すと予定日から外れて満額扱いになる）。休み申請は `ShiftChangeRequest`（TO_OFF）で記録。

## 画面
- 送付済みの請求の詳細（`/admin/invoices/[id]`）：「メールを再送する」欄（登録済みの宛先をチェックで選び、新しい宛先を追加できる。追加した宛先は取引先の `invoiceEmails` に保存。請求ごとに宛先(`recipientEmails`)を決めている請求は、その請求だけに保存）と、送付履歴（`InvoiceSendLog`：初回送信・再送の日時・宛先）。再送は金額・請求番号・状態・`sentAt` を変えず、件名は「【請求書（再送）】」。「送信」「再送する」を押すと、先に確認画面（初回送信=青・再送=オレンジのラベル＋実際に送る件名・宛先・添付・本文。`previewInvoiceMail` で送信と同じ中身を作る）が出て、「送信する/再送する」で初めて送られる。
- 請求管理（`/admin/invoices`）：送付済みの月を選ぶと、合計売上（税抜・税込）・支払い予定（スタッフ報酬＋経費＋別途報酬＋広告費＋外注費）・粗利、スタッフ別の内訳を表示。粗利に固定費・税金は含まない。
- スタッフ詳細（`/admin/staff/[id]`）：月別の売上・報酬＋経費・別途報酬・粗利・振込済みと累計。
- 会社経費（`/admin/company-expenses`）：区分「外注費」（他社からの請求・税抜）だけが支払い予定・粗利に入る。自動繰り返しはない（毎月手で登録）。

## 取引先ごとの運用
- **東北テレメディア開発（テレメ）**：村上潤之介 月55万円（16稼働想定・欠勤減算なし）＋交通費実費＋広告費（ELVIAの消化金額＝Meta実費）。請求書は1枚「業務委託費一式」、内訳書は店舗別（稼働費を日数按分・端数は日数最多の店舗、交通費は稼働した店舗の実費、広告費は開催店舗、店舗別に消費税を配分して合計を請求書と一致させる）。内訳書の呼び方は「稼働費」。交通費は自動だと日数按分になるので毎月実費に手で直す。広告は手数料を乗せない（村上を55万で使ってもらう前提）。送付先 kddi_kanri@telemedia.co.jp。
- **株式会社New Sense**：森田千尋 月額55万円・欠勤は日割り控除（予定日数で割る。2026年10月＝20日→1日27,500円）。内訳書に森田のシフトを載せる。単価は修正画面の業務委託費で変更可。森田の金額入力リンクもあり（送付済みの月は使えない。送付前に入力し直すと下書きを上書きするので注意）。
- **株式会社Faice**：月額のスタッフ多数。欠勤は「月額 ÷ 予定日数 × 出勤日数」。鮱名は交通費込み（請求しない。スタッフには1日400円を払う＝K.J負担）。渡辺のスポットは日額24,000円＋交通費申請額。
- **株式会社ULTI-ME**：加藤柊 月40万円・交通費込み（2026年10月〜）。稼働場所は「青森県内　携帯電話等販売ブース」。営業協力費は別途請求（EXTRA）。
- **株式会社OSUPLUS**：篠山（勤怠未登録の外部スタッフ）日額24,000円＋交通費。仕入れは株式会社Aver（日額23,000円）で上乗せ1,000円/日はこれで良い。
- **翔桜建設**：外崎 日額18,000円（交通費込み）。

## スタッフ・報酬
- 1日あたりの交通費の自動加算（`Staff.dailyTravelInclTax`）：亀井は2026年11月から撤廃（null）。10月分の交通費は経費3,200円（承認: 伊藤拓也）に置き換え。他のスタッフは変更なし（鮱名は1日400円のまま）。
- 振込の支払い予定金額 = 受取金額 + 申請のある経費 + 承認済み・未振込の別途報酬（固定支払のスタッフ）。振込完了を押すと、その別途報酬も振込済みになる（別途報酬の画面でも二重に払わない）。
- 亀井・齋藤以外のスタッフは個人事業主でインボイス登録あり。報酬は税込で支払い。
- リファラル（別途報酬 `CompensationRequest` REFERRAL）：
  - 渡辺紹介（丸山・藤田・柴田・寺島）：請求額の10%を会社取り分、残りから本人報酬を引いた額が渡辺のリファラル。
  - 齋藤 → 亀井に固定3万円/月。
  - 半崎 → 外部に固定5.5万円/月（会社経費の外注費に毎月登録）。
- 渡辺は月30万円固定の社内スタッフ（管理・リクルート）。
- 固定費の目安：事務所家賃10.5万・新宿の家賃20万・税理士4.4万（ざっくり。システムには登録しない）。
